# Blizzless Runewords

Справочник рунных слов, рецептов Хорадрического Куба и планнер персонажей для частного сервера Diablo II Blizzless. Каталог включает **оригинальные и переработанные рунворды**, которые реально используются на сервере — с рунами, типами предметов, уровнем и подсказками по отличиям от классики.

**Опубликованная версия:** [raferty.github.io/blizzless-runewords](https://raferty.github.io/blizzless-runewords/)

---

## Возможности

- компактная таблица и адаптивная сетка в графитовой теме на чёрном фоне;
- отдельный столбец класса в таблице; пунктирные границы панелей и элементов;
- поиск по названию, руне или типу предмета; клавиша `/` переводит фокус в поиск;
- фильтры по основе, сокетам и версии, жёлтые активные фильтры и общий сброс;
- локальный `UiSelect` для основы и сортировки: клавиатура, поиск по первым
  буквам, собственный выпадающий список в теме приложения;
- сортировка по названию, уровню и сокетам; в таблице заголовки названия
  и уровня переключают направление сортировки;
- избранное с сохранением в `localStorage`;
- вкладки баз в сетке и модалке для рецептов с отдельными наборами свойств;
- модалка с порядком рун, копированием рецепта и раскрываемой оригинальной версией;
- открытие подробного описания по всей площади карточки, включая пустое место;
- выбор рун в сайдбаре — подсветка «собранных» рун и полных рецептов;
- русский и английский интерфейс (язык сохраняется в `localStorage`).

В таблице выбор рун сохраняет все результаты и подсвечивает совпадения; полные
рецепты показаны первыми. В сетке остаются рецепты хотя бы с одной выбранной руной.
Выбор базы синхронизирован между карточкой и модалкой, в том числе при смене языка.

Сетка содержит до четырёх колонок на обычном десктопе, пять от 2200 px и шесть
от 2800 px; от 3400 px число колонок подстраивается под ширину с минимумом
карточки 420 px. Карточки одного ряда одинаковы по высоте. На телефоне панель
рун размещается над каталогом; широкая таблица прокручивается горизонтально
внутри своего блока. Увеличенные иконки и названия рун помещаются в 9 колонок
на экранах до 374 px и в 11 колонок на экранах от 375 до 600 px.

Дизайн перенесён 23.10.2026 из [Blizzless Runewords Reforged](https://blizzless-runewords-reforged.dearowlet20.chatgpt.site/).
Каталог данных при переносе сохранён.

**Стек:** Vue 3, TypeScript, Vite, Pinia, SCSS.

## Данные

Каталог содержит 105 уникальных рецептов. Основной состав сверён 22.10.2026 с [Blizzless Glossary](https://blizzless.info/ru/runewords) и его [публичным API](https://blizzless.info/api/runewords). Для каждого рецепта используется последняя опубликованная версия Blizzless, а при её отсутствии — официальная версия. Бонусы в карточках включают свойства вставленных рун.

Данные хранятся локально в `src/shared/*runewords.ts`. Hustle представлен отдельно для брони и оружия. Каталог включает 51 переработанный, 6 новых и 6 доступных только в RotW рецептов; эти группы могут пересекаться.

Wonder добавлен 23.10.2026 по [опубликованному описанию четвёртого сезона](https://blizzless.info/changelogs/season4):
Ohm → Lem → Ist, посох с тремя сокетами, требуемый уровень 57. В API он пока
помечен `isPublished: false`; для Flame Wave используется указанный в обновлении
триггер при попадании (on Striking). Описание RU/EN включает бонусы вставленных рун.

## Рецепты Куба

Раздел `#/recipes` содержит 98 актуальных рецептов из [каталога Blizzless](https://blizzless.info/cube):
57 добавленных, 29 переработанных и 12 без изменений. Переключение между рунными
словами, рецептами и планнером находится в шапке слева от поиска. Внутри раздела
Куба дополнительных вкладок нет.

Доступны поиск по названию, ингредиентам, результатам и примечаниям на RU/EN,
фильтры по версии, категориям и типам ингредиентов, просмотр оригинальных рецептов.
Версии объединяются через «ИЛИ», выбранные категории и типы ингредиентов — через «И».
Кнопки «Сферы», «Осколки» и «Инготы» работают как выбор сокетов: можно выбрать
несколько материалов через «ИЛИ», с остальными фильтрами они сочетаются через «И».
Учитываются только требуемые ингредиенты, получаемый материал не влияет на фильтр.
«Сбросить всё» очищает выбор.
Карточка открывает полное описание по всей площади и с клавиатуры. Поиск и фильтры
разделов сохраняются независимо при переключении до перезагрузки страницы.
Ингредиенты показываются в исходном порядке из каталога Blizzless — в карточке,
модалке и сравнении с оригиналом. Состав и количества сохраняются.
Ингредиенты собраны в общий пунктирный блок: иконка сверху, название по центру
снизу. Узкие карточки показывают по два ингредиента в строке.
Цвет результата соответствует качеству предмета: крафтовый — оранжевый,
редкий — жёлтый, магический — синий, уникальный — золотой.

Данные и изображения хранятся локально в `src/shared/cube-catalog.json` и
`public/images/cube/`; все руны, включая очищенные, используют те же файлы из
`public/images/`, что и фильтр рунных слов. При импорте они сопоставляются с `RUNES`
по названию руны независимо от формата ключа в API; совпадение проверяет `npm test`.
Приложение не обращается к API во время работы. Снимок сверён 23.10.2026:
из 129 версий выбирается последняя опубликованная Blizzless-версия по ключу,
иначе официальная; 31 рецепт содержит оригинальную версию для сравнения.
Если перевод примечания отсутствует в источнике, показывается доступный язык.

Обновление снимка из публичных GET-методов `/api/cube/recipes`, `/ingredients`,
`/ingredients-tags`, `/recipes-tags`:

```bash
npm run sync:cube
npm test
```

Команда скачивает данные и изображения, проверяет ссылки ингредиентов и сохраняет
исходный снимок в игнорируемый каталог `docs/audits/YYYY-MM-DD/cube/`.
Новые количества записей и изменения контракта следует проверить перед публикацией.

## Планнер персонажей

Раздел `#/planner` добавлен 26.10.2026. Компоновка подготовлена по скриншотам
[Maxroll D2Planner](https://maxroll.gg/d2/d2planner): экипировка и инвентарь слева,
три дерева навыков в центре, характеристики справа. На небольших экранах панели
перестраиваются в колонки. Доступны отдельные окна «Экипировка», «Навыки»,
«Наёмник», «Задания», «Заметки» и общий обзор. RU/EN поддерживаются во всех окнах.
В общем обзоре окно наёмника с выбором типа, уровнем и тремя ячейками экипировки
расположено сразу под инвентарём персонажа в левой колонке и сворачивается.
Ниже расположен сворачиваемый Stash с сеткой личного сундука 16×13.
Предметы можно перетаскивать по сеткам; куб и талисманы — между инвентарём
и сундуком. Размеры предметов, занятые ячейки и границы проверяются до переноса;
выбранные позиции сохраняются в сборке и экспорте `.d2s`.
Новый персонаж каждого класса получает Horadric Cube (2×2), максимальный
Annihilus и максимальный классовый Hellfire Torch с фиксированными +3 навыками.
Старые черновики однократно дополняются отсутствующими предметами;
существующие вещи и сохранённые снимки не заменяются. Ключи автоматически не добавляются.
Над заметками доступна компактная сворачиваемая таблица наград заданий.
В редакторе вариативные свойства рунвордов, уникальных и комплектных вещей
можно задать числом в пределах разрешённого диапазона. Класс бонуса Torch
выбирается отдельно; величина бонуса всегда +3.
Во вкладке «Экипировка» правая колонка прижата к краю страницы; инвентарь
занимает свободную область слева и увеличен в 1,5 раза, до 600 px.
На узких экранах его ширина подстраивается под доступное место.
Наведение или фокус на предмете открывает компактную подсказку с основой,
свойствами и составом рунного слова. Поверх изображения показаны сокеты:
руны в правильном порядке или пустые ячейки. Это работает для героя, наёмника
и талисманов; клик по-прежнему открывает редактор. Подсказки наследуют шрифт сайта.
Обычные кнопки, селекты и однострочные поля планнера и его модальных окон
используют общие размеры: высота 36 px, шрифт 13 px, строка 20 px. Эти размеры
сохраняются на мобильных экранах; игровые ячейки и деревья масштабируются отдельно.
Метрики задаются в `src/assets/planner-controls.scss` и CSS-переменных планнера.
Заполненные сокеты показывают вставку целиком без круглой обводки; круг остаётся
только у пустых. Размер вставок привязан к ячейке инвентаря и уменьшается при тесной раскладке.
В шлемах три сокета расположены треугольником: два сверху и один снизу по центру.
ПКМ по предмету открывает меню «Редактировать» / «Удалить». Оно учитывает
активный комплект оружия, работает у наёмника и талисманов, закрывается по Escape
или клику вне меню. С клавиатуры доступно через Shift + F10.

Визуальное оформление использует чёрные панели, синие активные элементы,
игровую панель экипировки и каменные деревья с иконками. Изображения найдены
в открытых источниках: панель инвентаря D2R — [LootCube](https://lootcube.net/en/builds/abyss-warlock),
фон дерева навыков — [Wowhead](https://www.wowhead.com/diablo-2/skill-calc),
портреты восьми классов и резервные/серверные иконки навыков — [Blizzless Glossary](https://blizzless.info/ru/skills).
Стандартные ветки используют оригинальные слои стрелок/ячеек и спрайты иконок Wowhead;
для изменённых веток расположение и зависимости сверяются с Blizzless перед выбором слоя.
Для варлока, которого нет в калькуляторе Wowhead, ячейки и соединения собраны
из тех же оригинальных графических слоёв по зависимостям Blizzless.
Портреты показаны и в каждом пункте выбора класса — в шапке и сводке характеристик.
Файлы хранятся локально в `public/images/planner/` и `public/images/skills/`;
источники перечислены в `public/images/planner/NOTICE.md`. Управление ячейками,
деревьями и связями реализовано в Vue/CSS/SVG. Изображения из пользовательских
скриншотов в приложение не включены.

Деревья используют полную декоративную панель Wowhead с исходными пропорциями
1162 × 1507: название сверху, отдельный счётчик очков, небольшие иконки с рангом
справа, сброс отдельной ветки и учтённый бонус навыков от снаряжения внизу.
Порядок веток семи исходных классов сверен с Wowhead; Чернокнижник использует
порядок Blizzless. При ширине панели до 840 px деревья идут вертикально,
сохраняя удобный размер иконок. Требуемый уровень под деревьями относится к
распределению навыков и учитывает отмеченные награды заданий.

- Восемь классов Blizzless, включая Чернокнижника: по три ветки и 30 навыков,
  всего 240. У друида 9/11/10 навыков по веткам, как в серверных таблицах.
  У каждого класса свой черновик, характеристики и коэффициенты роста.
  Для волшебницы, некроманта и чернокнижника энергия даёт 3 маны за очко.
  Поддержаны Focus Minions, Call of the Wild, серверные зависимости и названия
  мастерств варвара. Локально сохранены все 240 иконок и описания RU/EN;
  58 изменённых навыков отмечены по сравнению с исходными таблицами клиента.
- Распределение очков учитывает уровень 1–99, предел 20 вложенных очков в навык,
  зависимости и полученные награды заданий. Необходимые навыки изучаются автоматически.
  Уровень можно снизить до 1 даже после распределения: недоступные навыки и лишние
  очки возвращаются, характеристики пропорционально сокращаются до нового лимита.
  Экипировка и награды заданий сохраняются; повышение уровня оставляет новые очки свободными.
  Клик добавляет очко, Shift + клик доводит навык до доступного максимума,
  правый клик / Delete снимает очко. Снятие последнего очка с родительского навыка
  сбрасывает зависимые навыки и возвращает их очки, как в Wowhead.
  Shift + ПКМ снимает доступные вложенные очки; Ctrl показывает базовые ранги
  без снаряжения. Изученные навыки показывают итоговый уровень с бонусом вещей;
  повышенные ранги и иконки выделяются синим, без звёздочки. Наведение и фокус
  клавиатуры открывают игровую подсказку с
  описанием, рангом, требованиями и синергиями; Escape её закрывает.
  На сенсорном экране описание открывается при нажатии и имеет кнопку закрытия.
- Десять ячеек экипировки, два комплекта оружия, подбор рунных слов из локального
  каталога по типу ячейки и классовой основе, повторное использование сохранённых вещей.
  Окно предмета разделено на «Выбор» и «Редактирование»: категории слева,
  поиск, фильтры уровня/класса основы и цветной список справа. Базы, уникальные
  и комплектные вещи загружаются из локальных игровых данных Blizzless;
  крафтовые предметы доступны из сохранённых вещей. Ручное создание и блок
  «Название, качество и бонусы в сводке» временно убраны из редактора.
  У сетовых вещей в редакторе и подсказке показаны постоянные свойства,
  условные бонусы предмета, бонусы за части сета и полный комплект. Для каждого
  условного свойства указаны количество частей или конкретная нужная вещь.
  Изображение в редакторе соответствует игровой базе и особому виду уникальной/
  комплектной вещи: локальный каталог использует `invfile`, `uniqueinvfile`,
  `setinvfile`, качество и ступень основы. Ресурсы обновляются командой
  `npm run sync:planner-items` после обновления игровых таблиц.
  В ячейках персонажа, наёмника и талисманов показаны изображения с учётом их
  игрового размера; названия доступны при наведении. Старые unique/set без
  кода базы распознаются по имени без изменения сохранённой сборки.
  Есть повторное использование своих вещей, смена основы, минимальный/максимальный
  ролл, уровень предмета, эфирность и число сокетов. В каждом сокете обычной,
  уникальной или комплектной вещи можно выбрать, заменить и удалить руну или
  камень: есть поиск RU/EN и фильтры «Руны»/«Камни». Доступны 37 рун Blizzless
  (включая четыре чистые) и 35 камней всех ступеней качества. Свойства вставок
  берутся из игровых таблиц с учётом оружия/брони/щита; поддерживаемые плоские
  бонусы входят в сводку, требуемый уровень учитывает вставки. В рунных словах
  состав фиксирован рецептом. Вставки видны поверх изображения и в подсказке,
  сохраняются со сборкой и экспортируются настоящими дочерними предметами .d2s.
  Каталог/изображения обновляются через `npm run sync:planner-sockets` после
  `npm run sync:planner-save`.
  Для основы можно выбрать обычное, магическое или редкое качество. У magic/rare
  есть «Добавить свойство»: поиск, префиксы/суффиксы, настройка значений в игровых
  пределах и удаление. Каталог из 921 аффикса Blizzless фильтруется по основе,
  уровню, качеству и группам; magic допускает 1+1, rare — 3+3. Не совместимые
  с новой основой/качеством/уровнем свойства убираются из черновика с сообщением.
  `npm run sync:planner-affixes` пересоздаёт каталог из локальных native-save таблиц.
  Необязательный `affixes: { id, values }[]` сохраняет игровые ID и выбранные значения;
  импорт проверяет их, а .d2s содержит настоящие ID префиксов/суффиксов и свойства.
  Плоские бонусы, классовые и бонусы веток навыков учитываются у активного героя;
  полное описание всех модов видно в подсказке. Полная симуляция боя не добавлена.
  Кнопка «В сундук» переносит надетую вещь, «Удалить» снимает её; изменения полей
  сохраняются через «Применить». Старые сборки v1 совместимы, игровые параметры
  хранятся в необязательных полях `baseCode`, `catalogId`, `itemLevel`, `sockets`,
  `socketedItems`, `affixes`, `ethereal`, `propertyRoll`. `socketedItems` содержит коды игровых
  рун/камней либо `uniqueNNN` для фасетов и колоссальных самоцветов; `null` — пустое
  гнездо. `socketPropertyValues` хранит выбранные роллы по индексу сокета (с нуля)
  и номеру свойства. Значения проверяются по диапазонам Blizzless. Доступны 8
  вариантов Rainbow Facet и 6 новых самоцветов, включая Guardian’s Light.
  `.d2s` сохраняет их как вложенные уникальные предметы с собственными свойствами;
  прежние сборки без этих полей совместимы.
  Для всех 105 рунных слов автоматически заполняются поддерживаемые плоские
  бонусы и бонусы навыков класса, включая вставленные руны. Доступны минимальный
  и максимальный роллы, выбор варианта оружие/щит/броня. Ранее сохранённые ручные
  бонусы и заметки сохраняются при применении предмета.
  У Чернокнижника доступны гримуары, у друида — классовые шкуры.
- Инвентарь талисманов 10 × 4 с проверкой размеров и пересечений; сундук на
  100 запасных предметов, обмен предмета сундука с выбранной ячейкой экипировки.
- Золото под инвентарём: ввод суммы и «Максимум» по уровню персонажа
  (10 000 × уровень, до 990 000). При снижении уровня сумма ограничивается новым
  максимумом. Сохраняется в черновиках, JSON/share и поле `gold` игрового `.d2s`;
  старые сборки без суммы получают 0. Лимит: [The Arreat Summit](https://classic.battle.net/diablo2exp/basics/).
- Наёмники актов I, II, III и V с отдельным уровнем,
  специализацией и экипировкой. При смене типа их снаряжение переносится в сундук.
  Экипировка показана на оригинальном фоне наёмника D2R из LootCube: три активные
  ячейки (шлем, оружие, доспех) открывают общий редактор предмета.
  Уровень наёмника может совпадать с уровнем героя, но не превышает его и общий
  предел 98. При снижении уровня героя наёмник ограничивается автоматически;
  старые сохранения с уровнем 99 приводятся к допустимому пределу без потери сборки.
  Правило: [официальный справочник Blizzard](https://classic.battle.net/diablo2exp/basics/hirelings.shtml).
- Блоки «Основные навыки» и пояснение «О расчётах» под характеристиками временно
  убраны из интерфейса. Поле `primarySkills` сохраняется в формате v1 для совместимости.
- Раздел «Расчёты» и переключатель над деревьями удалены; панель навыков сразу
  показывает три ветки класса.
- Панели «Автор»/«Описание сборки» справа и отдельная панель «Наборы сборки»
  удалены. Название сборки и управление наборами находятся в верхней строке
  рядом с классом, уровнем и действиями сборки. Наёмник находится справа над
  характеристиками; автор и описание редактируются в заметках.
- Наёмник, характеристики и заметки сворачиваются нажатием на заголовок,
  в том числе с клавиатуры. Поля сохраняются при сворачивании. Заголовок
  характеристик остаётся доступным при прокрутке их содержимого.
- Блоки «Лут-фильтр» и «Сильные и слабые стороны» под наёмником удалены;
  их поля доступны в заметках.
- Матрица наград заданий для трёх сложностей: навыки, характеристики, жизнь,
  сопротивления. Снижение уровня или снятие наград отклоняется, если уже вложенные
  очки выходят за новый лимит; распределение сохраняется.
- Вкладка Waypoints: 39 точек по актам I–V отдельно для Normal, Nightmare и Hell,
  сворачиваемые сложности, «Отметить все» / «Снять все». По умолчанию открыты все;
  старые сборки без этого поля сохраняют прежнее поведение. Выбор хранится в
  черновиках, JSON, ссылках и переносится в `.d2s`.
- Автор, описание, сильные и слабые стороны, заметки и текст/ссылка лут-фильтра.
- Автосохранение черновиков и до 50 независимых снимков сборок в `localStorage`
  (`blizzless-planner-v1`), JSON-импорт/экспорт и ссылка со снимком сборки.
  После открытия ссылки сборка становится редактируемым локальным черновиком.
  Неверный импорт не заменяет текущую сборку. Формат собственный, версия 1;
  импорт Maxroll JSON и игровых файлов `.d2s` не поддерживается.
- Кнопка «Экспорт» создаёт двоичный `.d2s` v105 для офлайн Blizzless 1.3.2:
  восемь классов, уровень/опыт, навыки, характеристики, награды заданий,
  оба комплекта оружия, экипировка, талисманы, личный сундук и наёмник.
  В диалоге задаются игровое имя (2–15 латинских букв) и точные основы вещей;
  для уникальных/комплектных вещей выбирается игровой предмет. Рунворды получают
  полные серверные свойства и руны. Режим «Из планнера» сохраняет введённые
  бонусы, включая промежуточные роллы, с вычетом уже учтённых бонусов вставленных
  рун; остальные свойства используют выбранный в редакторе ролл (максимальный для старых сборок). Доступны полные min/max
  пресеты. Обычные/магические/
  редкие вещи используют введённые бонусы; произвольное название заменяется игровым.
  Это новый персонаж для проверки сборки с открытыми сложностями и актами;
  WP открываются по выбору во вкладке Waypoints.
  дополнительные файлы `.map`, `.key`, `.ctl` не генерируются. JSON остаётся
  отдельной резервной копией, включая заметки и другие поля планнера.
  Невместимые в игровые поля значения блокируют скачивание: например, у Lightning
  +300 mana превышает предел `maxmana` (223); минимальный ролл +200 экспортируется.
  Данные/лицензии: `public/data/planner-save/`, обновление `npm run sync:planner-save`.
  Данные берутся из того же launcher manifest, что и каталог планнера; проверяются
  размер и SHA-256. Экспорт проверен двумя независимыми парсерами и скачиванием
  через браузер. Проверки в запущенной игре в этом окружении не было.

**Источник данных:** текущий Blizzless 1.3.2, сверка 26.10.2026.
`charstats.txt`, `skills.txt`, `skilldesc.txt`, `runes.txt`, `gems.txt`,
`difficultylevels.txt`, `inventory.txt` и строки локализации скачаны из публичного
[манифеста лаунчера Blizzless](https://blizzless.info/api/launcher-mods/manifest).
Каждый файл проверяется по размеру и SHA-256. Манифест `1792771561313`,
активный [датасет навыков](https://blizzless.info/api/skills/default-dataset)
`6ada53efa3680a208170ae3d` / 1.3.2; позиции и уровни всех навыков сверены
между игровыми таблицами и API. Хеши и версия записаны в `source` снимков.
Правила очков сверены с [The Arreat Summit](https://classic.battle.net/diablo2exp/skills/basics.shtml),
награды — с [официальным справочником заданий](https://classic.battle.net/diablo2exp/quests/rewards.shtml).

**Границы расчётов:** суммируются поддерживаемые бонусы активной
экипировки героя и талисманов; запасное оружие, сундук и вещи наёмника в итог
не входят. Коэффициенты жизни/маны/выносливости берутся из серверных таблиц.
Используются пределы
сопротивлений −100…75% с учётом сложности и Ани. Ауры, эффекты навыков,
синергии, урон, брейкпоинты, отдельные навыки/ветки с предметов, модификаторы
за уровень и процентные модификаторы жизни/маны/максимальных резистов не вычисляются.
Остальные свойства рунворда доступны в справке; сохранённые собственные предметы
и их бонусы поддерживаются форматом сборки.
Подбор рунворда проверяет тип и число доступных сокетов конкретной основы.
Совместное использование двуручного оружия и предмета в левой руке, требования
силы/ловкости и полные бонусы комплектов пока не рассчитываются.

Данные: `src/shared/planner-catalog.json`, `src/shared/planner-runewords.json`,
оформление классов: `src/shared/planner-presentation.json`, иконки: `public/images/skills/`,
метаданные окон: `src/shared/planner.ts`, автозаполнение: `src/utils/planner-runewords.ts`,
валидатор и формулы: `src/utils/planner.ts`, состояние: `src/store/planner.ts`,
интерфейс: `src/components/CharacterPlanner.vue` и `src/components/planner/`.
Раздел загружается отдельным чанком. Runtime-запросов к внешнему API нет.
Обновление снимка из текущих игровых файлов сервера (сырые данные и манифест
сохраняются в игнорируемом `docs/audits/YYYY-MM-DD/planner-server/`):

```bash

npm test
```

После обновления снимка полностью перезагрузите открытую dev-вкладку:
при HMR уже созданное состояние Pinia может удерживать прежний список классов.

- npm или yarn

```bash
npm install

yarn install

yarn build

yarn typecheck

```

Проверяет 105 рунных слов, разделение свойств по базам, фильтры, сохранение

## Переменные окружения

`VITE_RELEASE_DATE` — дата релиза в формате `YYYY-MM-DD`. Она передаётся в приложение при сборке и отображается справа в шапке, перед переключателем языка, как «Актуально на dd.mm.yyyy» (или `As of` в английском интерфейсе).

```bash
VITE_RELEASE_DATE=2026-10-22 npm run build
```

Если дата не задана, используется дата сборки по московскому времени. Значение фиксируется в собранном приложении. Переменную также можно задать в `.env.local` или `.env.production.local` для соответствующего режима Vite.

Базовый путь задаётся в `vite.config.ts`.
